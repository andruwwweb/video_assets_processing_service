# Техническое задание

## Проект: Media Processing Platform

### Версия документа

1.0

### Тип проекта

Web Application + Public API Platform

---

# 1. Описание проекта

Media Processing Platform — это платформа для загрузки, обработки и распространения видео-контента.

Система предоставляет пользователям и внешним приложениям возможность:

* загружать видео;
* получать превью и метаданные;
* конвертировать видео в различные форматы и разрешения;
* извлекать аудиодорожки;
* генерировать субтитры;
* получать результаты через API, WebSocket и Webhooks.

Платформа должна быть построена как API-first решение и поддерживать горизонтальное масштабирование.

---

# 2. Цели проекта

Разработать систему, которая:

* обеспечивает автоматическую обработку видео;
* предоставляет удобный веб-интерфейс;
* предоставляет публичный API для интеграций;
* поддерживает асинхронную обработку задач;
* может использоваться как SaaS-сервис обработки медиа.

---

# 3. Целевая аудитория

## Разработчики

Используют API платформы для интеграции обработки видео в собственные продукты.

## Владельцы контента

Используют веб-интерфейс для загрузки и обработки видео.

## Компании

Используют платформу как внутренний сервис обработки медиаконтента.

---

# 4. Основные сценарии использования

## Сценарий №1. Обработка через веб-интерфейс

Пользователь:

1. Загружает видео.
2. Видит прогресс обработки.
3. Получает готовые артефакты.
4. Скачивает результаты.

---

## Сценарий №2. Использование через API

Клиентское приложение:

1. Загружает видео через API.
2. Получает идентификатор задачи.
3. Отслеживает статус обработки.
4. Получает уведомление через Webhook.
5. Загружает готовые файлы.

---

# 5. Функциональные требования

## 5.1 Загрузка видео

Система должна поддерживать загрузку файлов следующих форматов:

* MP4
* MOV
* MKV
* WEBM
* AVI

После загрузки должен создаваться объект видео и задача обработки.

---

## 5.2 Извлечение метаданных

После загрузки необходимо автоматически определить:

* длительность видео;
* размер файла;
* разрешение;
* FPS;
* видеокодек;
* аудиокодек;
* битрейт;
* соотношение сторон.

---

## 5.3 Генерация превью

Система должна создавать:

* миниатюру видео (thumbnail);
* набор кадров по заданному интервалу (опционально).

Результат должен сохраняться как отдельный артефакт.

---

## 5.4 Генерация короткого клипа

Система должна создавать короткую демонстрационную версию видео.

Параметры:

* длительность клипа;
* точка начала;
* качество.

По умолчанию используется клип продолжительностью 10 секунд.

---

## 5.5 Транскодирование видео

Система должна создавать версии видео в нескольких разрешениях:

* 360p
* 480p
* 720p
* 1080p

Каждая версия сохраняется как отдельный файл.

---

## 5.6 Генерация HLS

Система должна создавать адаптивный стриминговый формат:

* playlist.m3u8
* сегменты видео

Полученные файлы должны быть пригодны для онлайн-воспроизведения.

---

## 5.7 Извлечение аудио

Система должна поддерживать экспорт аудиодорожки в форматы:

* MP3
* AAC
* WAV
* OGG


# 6. Работа с задачами

Все операции обработки должны выполняться асинхронно.

После загрузки видео система должна:

1. Создать задачу обработки.
2. Поместить задачу в очередь.
3. Вернуть пользователю идентификатор задачи.
4. Выполнить обработку в фоне.

HTTP-запрос не должен ожидать завершения обработки.

---

# 7. Обновление статуса в реальном времени

Система должна поддерживать WebSocket-соединение.

Пользователь должен получать:

* начало обработки;
* прогресс выполнения;
* завершение обработки;
* ошибки обработки.

Пример данных:

* 0%
* 25%
* 50%
* 75%
* 100%

---

# 8. Публичный API

Система должна предоставлять REST API.

Основные возможности:

* загрузка видео;
* получение статуса обработки;
* получение списка артефактов;
* удаление видео;
* управление Webhooks;
* управление API-ключами.

---

# 9. Webhooks

Система должна позволять пользователю зарегистрировать URL для получения уведомлений.

Поддерживаемые события:

* обработка завершена;
* обработка завершилась ошибкой;
* создан новый артефакт.

---

# 10. API-ключи

Каждый пользователь должен иметь возможность:

* создавать API-ключи;
* отключать API-ключи;
* удалять API-ключи.

Для каждого API-ключа должна храниться история использования.

---

# 11. Ограничение запросов

Система должна поддерживать ограничение количества запросов.

Минимальная конфигурация:

* 100 запросов в минуту на API-ключ.

---

# 12. Личный кабинет

Пользователь должен иметь доступ к панели управления.

Функциональность:

* список видео;
* история обработок;
* состояние задач;
* управление API-ключами;
* управление Webhooks.

---

# 13. Документация API

Система должна содержать раздел документации.

Разделы:

* Начало работы
* Аутентификация
* Работа с видео
* Работа с артефактами
* Webhooks
* Ошибки
* Ограничения API

---

# 14. API Sandbox

Система должна предоставлять интерфейс для тестирования API.

Пользователь должен иметь возможность:

* отправлять запросы;
* загружать файлы;
* просматривать ответы сервера;
* видеть примеры запросов.

---

# 15. Нефункциональные требования

Система должна обеспечивать:

* асинхронную обработку задач;
* горизонтальное масштабирование воркеров;
* отказоустойчивость очередей;
* логирование всех операций;
* возможность контейнеризации;
* возможность автоматического деплоя.

# 17. Критерии готовности MVP

Система считается готовой, если пользователь может:

1. Загрузить видео.
2. Получить статус обработки.
3. Наблюдать прогресс через WebSocket.
4. Получить превью.
5. Получить аудио.
6. Получить версии видео в нескольких разрешениях.
7. Использовать REST API.
8. Получать Webhook-уведомления.
9. Работать через веб-интерфейс и Sandbox.
